# P0 가능성 검토 결과와 후속 구현 범위

2026-10-28, 기준 `e18d682` 및 기존 미커밋 조사 자료.
사용자 지시에 따라 **P0는 가능성 검증과 문서화로 종료한다.**
새 기능·호환 계층·시제품·검증 도구의 추가 구현은 P0에서 진행하지 않는다.
아래 판정은 기존 소스 조사와 실행 기록을 종합한 결과이며, 17차 정리에서는 문서만 변경했다.

## 판정

| 대상 | 가능성 판정 | 근거 | 남은 조건과 담당 단계 |
| --- | --- | --- | --- |
| GNU nano 이식 | 조건부 가능 | 실제 편집 코어의 양 아키텍처 ELF, x86 IDE/AHCI 한글 열기·저장·종료와 재부팅 후 파일 검증 | 필수 기능 전체 연결·기존 편집기 교체 P4, 통합·Pi 5 실기 P6 |
| MicroPython 내장 오류와 사용자 문자열 구분 | 조사한 경로에서 가능 | 생성 경계의 format·인수·출처를 보존한 호스트 시제품, 사용자 객체·args·출력 보존 | 모든 생성 경계·문구·REPL 적용 P5 |
| vendor 무수정 MicroPython 전체 번역 | 전체 가능 여부 미입증 | 일부 경계는 alias/strong wrapper 후보로 검증했으나 전체 메시지·수명·예산의 증명이 부족 | P5 설계에서 채택 여부와 미지원 경계를 판정 |
| 현재 payload64 인수 압축 | 허용 범위에서 가능, 공개 C 입력 전체에는 불충분 | 실제 count validator 두 경로에서 POS32 초과 입력 6개가 도달 | 64비트 인수의 저장 설계·구현 P5 |
| 커서·입력 모드·전체화면 표시 | 기존 콘솔 상태와 TTY 확장에 연결하는 설계 후보 | 콘솔별 lang_hangul, raw 이벤트·resize·렌더러 수명 계약 조사 | API·커서 P2, 화면 영역·표시 P3, 실행 검증 P6 |
| 일반 안내·오류 언어 분리 | 호출 문맥과 구조화된 인수를 이용하는 방향 | 출력 경로별 안내/오류/데이터/진단 분류와 MicroPython 활성 오류 목록 | 개별 catalog 작성·번역·적용 P5 |

조건부 가능은 조사한 경로의 실증과 필요한 의존성이 확보됐다는 뜻이다.
미입증은 가능 또는 불가능으로 확정하지 않은 항목이다. 특히 vendor 무수정 전체 번역을
보장하거나, 현재 압축 방식의 한계를 전체 요구의 불가능으로 일반화하지 않는다.
P0 문서 검토 완료와 사용자 기능의 구현·검증 완료는 별개다.

## nano의 후속 조건

고정 후보는 기존 조사 당시의 GNU nano 9.3이며, 출처·SHA-256·라이선스·설정은
[초기 조사](feature_p0.md)에 보존한다. 현재 최신 버전을 다시 조사한 결과는 아니다.
undo/redo를 유지하기 위해 tiny 빌드를 사용하지 않고, 외부 명령·signal·파일 속성 등은
설정과 호출 경계에서 지원 여부를 명시해야 한다.

필요한 계층은 private libc/POSIX·파일 스트림·bounded UTF·제한된 wide curses와 TTY
연결이다. 전체 ncursesw보다 작은 비용이라는 측정 결론은 없으며, 직접 계층은 관찰한
nano 호출을 연결한 후보다. 심볼·TTY 계약은 [초기 조사](feature_p0.md),
양 아키텍처 링크는 [링크 기록](feature_p0_nano_link.md), 실제 파일 동작은
[저장 검증](feature_p0_nano_storage.md)에 있다.

PREEDIT를 편집 버퍼·undo·저장 파일과 분리하는 원리는 호스트에서 확인했다.
실제 GUI의 픽셀 복구·포커스·모든 입력 프롬프트·밑줄 커서·필수 기능 전체와 Pi 5는
별도 확인이 필요하다. 기존 private nano 결과물을 기본 편집기로 자동 채택하지 않는다.

## MicroPython의 후속 조건과 대안

활성 `MP_ERROR_TEXT` 154개와 producer 타입은 목록화했지만, 이는 전체 오류 번역의
실행 coverage가 아니다. 비매크로 메시지·errno·동적 설명·traceback·전체 REPL과
생산 포트 연결은 남는다. [경계 감사](feature_p0_micropython_audit.md),
[typed 목록](feature_p0_mp_types.md), [최근 reporter·범위 판정](feature_p0_mp_pack_reporter.md)을
근거로 삼는다.

추가 번역 객체를 만드는 초기 방식은 고갈·등록 포화·emergency 재사용 때문에 채택할 수
없다. 후속 출처 저장 후보는 일부 수명 문제를 해결했지만 2MiB 호스트 힙 기준 metadata가
589,961바이트이고, mark closure의 최악 비용과 8단 출력 깊이 정책은 미정이다.
이 비용을 생산 4MiB 힙에 그대로 확정한 결과도 아니다.
POS32를 넘는 실제 공개 C 입력을 거부하는 현재 방식을 전체 지원으로 채택할 수 없다.

| P5에서 검토할 대안 | 장점과 제약 |
| --- | --- |
| 포트·빌드 경계의 출처 capture 확장 | vendor 소스 무수정 정책을 유지하는 후보이나 전체 경계·ABI·수명·메모리 비용을 구현 단계에서 해결해야 함 |
| 작업 복사본의 최소 hook 패치 | 생성·GC hook을 명시할 수 있는 대안이나 현 vendor 무수정 정책과 충돌하며 사용자 결정 전 적용하지 않음 |

P0에서는 어느 대안도 새로 구현하지 않는다. P5에서 전체 요구를 충족하지 못하는 경계가
확인되면 근거와 대안을 제시하고 정책을 결정한다. 영어 fallback으로 누락을 숨겨 완료
처리하지 않으며, 확정된 사용자 요구는 유지한다.

## 출력 목록과 단계 배분

[출력 경로 목록](feature_p0_outputs.md)은 안내/오류/사용자 데이터/개발 진단과 번역
경계를 정리한 조사 자료다. 모든 개별 문구의 완성된 catalog는 P5 산출물로 둔다.

| 단계 | P0에서 이관한 작업 |
| --- | --- |
| P1 | 포팅본 머꼬의 기본 프롬프트 변경과 해당 회귀 |
| P2 | 커서·입력 모드 조회 API와 콘솔 수명 연동 구현 |
| P3 | 전체화면에서도 유지되는 한/영 표시 영역 구현 |
| P4 | nano 필수 기능·호환 계층·PREEDIT 연결 완성과 기본 편집기 교체 |
| P5 | 전체 catalog·생성 경계·ABI capture·64비트 인수 저장·reporter·자원/깊이 정책의 설계와 구현 |
| P6 | IDE/AHCI/Pi 5 통합 UI·입력·저장·언어 검증 |

P0의 종료 기준은 가능성 판정·근거·제약·미입증 항목·후속 담당 단계가 문서에 남는 것이다.
새 구현을 통해 모든 제약을 해결하는 것을 P0의 선행 조건으로 두지 않는다.
조사 문서·실행 결과는 이력으로 보존하며, 기능 채택은 해당 구현 단계에서 검토한다.
이후 바로 진행할 독립 작업은 P1이며 이번 문서 정리에서는 착수하지 않았다.

## P0 1회성 코드 정리

사용자 요청으로 `64bit/tools/feature_*.py` 6개, `64bit/tests/test_feature_*.py` 6개와
`64bit/tools/p0/`의 실험용 C 코드·헤더 13개를 삭제했다. 문서·catalog JSON과 과거
검증 결과는 유지한다. 연결 문서의 옛 P0 probe 명령은 현재 checkout에서 재실행할 수
있는 도구 목록이 아니라 당시 검증 절차의 기록이다.

`prepare_nano64.py`는 기존 nano 빌드에 필요하고, nano 호환 계층·실제 편집 코어의
host 테스트와 `nano_storage_regression64.py`는 반복 실행하는 회귀 검증이므로 유지한다.
커널·앱·private nano 구현과 빌드 규칙은 이번 정리에서 변경하지 않는다.
18차 정리 후 증분 `make check64`를 통과했다(호스트 101개·style 290개 파일).
남은 빌드·테스트 코드의 삭제 파일 참조가 없고 보존 대상 216개 파일이 그대로임을 확인했다.
검증 로그는 `/tmp/mowkow-p0-cleanup-check64.log`이며 QEMU·Pi 5는 이번에 실행하지 않았다.

## 17차 문서 정리의 확인 범위

문서 링크·단계 배분·로그의 시행당 최대 3문장 규칙과 소스 무변경을 확인했다.
17차에서는 빌드·host probe·QEMU·Pi 5를 실행하지 않았다.
과거 실행 결과는 각 연결 문서의 날짜·설정·검증 범위를 따른다.
